# Backend and frontend

Short, because there is little here. There is no backend API, and the only frontend is a static marketing site that renders mock data.

## Backend

`backend/` contains three README files and `backend/models/schema.sql`. There is no FastAPI app, no endpoints, no request handlers, no authentication, no ORM models and no start command. `backend/README.md` and `backend/api/README.md` describe a planned FastAPI app (scoring endpoint, incident feed, dashboard data) in the future tense; `docs/DEVELOPER_GUIDE.md` correctly lists "a running backend API despite its README scaffold" as not implemented.

What `backend/` does contribute is the database schema. `schema.sql` is read from that path by `ingestion/storage.py` (and copied into the ingestion image by its Dockerfile). See `docs/data-pipeline.md` for the tables.

So today:

- Nothing serves scoring results over HTTP. Scoring is a polling process that writes to the `incidents` table (`docs/scoring-and-evaluation.md`).
- Nothing serves incidents to a client. The only ways to read them are SQL against `incidents`, or the markdown report stored in `incidents.report_text`.
- `ghast_latest_report.md` at the repo root is one such report, copied out by hand. It is not generated by any script in the repo.
- No auth of any kind exists. Nothing listens on a network port except the Postgres, MinIO and nginx containers.

## Frontend

`frontend/site/` is a static site: five HTML pages (`index`, `how-it-works`, `console`, `trust`, `project`), CSS and small scripts. No framework and no build step. `frontend/Dockerfile` copies the directory into `nginx:1.27-alpine`; the compose `frontend` service publishes it on `${FRONTEND_PORT:-3000}`. `frontend/dashboard/` is an empty directory.

All data goes through one facade, `GHAST.data` (`scripts/data/api.js`), which resolves to `sample.js` or `live.js` from `scripts/config.js`. Sample is the default. `live.js` calls the plan 02 endpoints, which do not exist yet, so live mode shows error states. The console and trust pages show sample data with a visible tag. See `frontend/site/README.md` for the module slots and which backend plan fills each.

Treat the site as a design artifact, not documentation of the system. Design rules and the handover guide are in `docs/frontend/` (`DESIGN.md` and `README.md`).
